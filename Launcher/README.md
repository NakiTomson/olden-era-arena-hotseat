# Olden Era — Арена для двоих

Неофициальный мод для **Heroes of Might and Magic: Olden Era**, который позволяет двум людям играть друг против друга на арене **за одним компьютером**.

Первый игрок выбирает и развивает героя, собирает армию и завершает подготовку. Затем подготовка автоматически передаётся второму игроку. Когда оба готовы, начинается бой: игроки по очереди управляют своими отрядами одной мышью и клавиатурой.

В комплект входит лаунчер, через который можно установить, включить и отключить мод.

## Что делает мод

- Позволяет выбрать во втором слоте арены **Игрока** или **Игрока-компьютер**. Игра против ИИ остаётся доступна при включённом моде.
- Передаёт подготовку второму человеку без дополнительного окна «ОК».
- Показывает второму игроку его собственные армию и заклинания, сохраняя выбор первого.
- Начинает шкалу подготовки второго игрока с этапа «Герой».
- Даёт обоим людям управление своими армиями в бою.
- Отключает общий таймер подготовки в арене для двоих, поскольку игроки готовятся по очереди. В арене против ИИ таймер работает как обычно.

Мод предназначен для локальной арены через меню хотсита. Оба игрока видят один экран, поэтому скрытность выбора не обеспечивается. **Быстрый старт** сохраняет обычного соперника-компьютер; для игры вдвоём используйте путь ниже.

## Как начать играть

Нужны установленная игра, Windows x64 и .NET Framework 4.8. Загрузчик BepInEx и подходящие библиотеки Unity входят в готовый комплект.

1. Распакуйте комплект в отдельную папку. Папки **Launcher** и **Mod1** должны лежать рядом — сохраняйте структуру архива.
2. Закройте игру и запустите `Launcher/OldenEraLauncher.exe`.
3. Укажите папку игры: в ней должны находиться `HeroesOldenEra.exe` и `GameAssembly.dll`.
4. Отметьте **Арена для двоих** и нажмите **Играть**. Первый запуск с BepInEx может занять несколько минут.
5. В игре откройте **Несколько игроков → Хотсит → Арена**.
6. Нажмите значок типа второго слота и выберите **Игрок**. Первый игрок должен остаться в своём слоте.
7. Нажмите **Начать игру**, последовательно подготовьте двух героев и играйте.

Для партии против ИИ выберите во втором слоте **Игрок-компьютер**.

Для отключения мода закройте игру, снимите отметку в лаунчере и нажмите **Применить**. Кнопка **Отключить все** отключает все моды, которыми управляет лаунчер.

## Поддерживаемая версия

- Мод: **0.2.1**.
- Игра: **Steam-сборка 25061458**, Windows x64.
- Работоспособность текущей версии подтверждена пользователем **13 сентября 2026 года**. Это ручная проверка; все сочетания героев, навыков и заклинаний не перебраны.

Совместимость повторов и работа вместе с другими модами не подтверждены. В журнале известна `NullReferenceException` при выходе из арены; её связь с модом не установлена, разбор отложен.

## Как проверять совместимость после обновлений

Проверка состоит из двух частей: **сверка файлов** и **короткая партия в игре**. Успешная сверка файлов сама по себе не доказывает, что все игровые сценарии работают.

1. **Перед обновлением игры** закройте её и отключите мод через лаунчер. Сохраните архив рабочей версии мода.
2. **После обновления** запустите игру без мода и убедитесь, что обычная арена работает.
3. **Сверьте `GameAssembly.dll`** по инструкции ниже. Это файл игровой логики; SHA256 — его цифровой отпечаток. Если он изменился, нужна проверка и адаптация мода под новую сборку. Текущая версия не поддерживает такой файл.
4. **Если отпечаток совпадает**, включите мод и выполните игровой список проверок ниже. Данные, интерфейс или загрузчик могли измениться независимо от `GameAssembly.dll`.
5. **Запишите результат:** версию мода, Steam build, SHA256 игры, дату, пройденные сценарии и найденные проблемы. Такой отчёт нужен для каждого нового сочетания версий игры и мода.

При включении и запуске через лаунчер отпечаток сравнивается автоматически. При несовпадении лаунчер сообщает, что сборка игры не поддерживается. Сам плагин также проверяет отпечаток и отказывается устанавливать свои перехваты на другой сборке. **Просто заменить хеш в настройках недостаточно:** в моде есть адреса методов и расположение игровых данных, привязанные к конкретной сборке.

Если обновился только мод, закройте игру, отключите старую версию, замените её файлы, включите новую и повторите тот же игровой список. При замене всего комплекта сначала отключите моды старым лаунчером.

### Игровой список проверок

- [ ] Во втором слоте можно переключить **Игрок-компьютер → Игрок → Игрок-компьютер**, не потеряв первого игрока.
- [ ] Арена против ИИ запускается, компьютер делает ходы. **Быстрый старт** также сохраняет ИИ.
- [ ] В арене для двоих первый игрок проходит подготовку; затем автоматически открывается доступный для кликов выбор второго героя.
- [ ] У второго игрока шкала начинается с «Героя» и заполняется по его этапам. На панелях показаны его армия и заклинания; выбор первого игрока сохранён.
- [ ] После готовности обоих начинается бой. Обе стороны управляются людьми; проверены движение, атака, ожидание, защита и применение заклинания.
- [ ] Партия доведена до результата, выход в меню работает. Новая арена в том же процессе снова корректно передаёт подготовку второму игроку.
- [ ] После отключения мода игра запускается и обычная арена работает.

Если возникла проблема, сохраните `BepInEx/LogOutput.log` из папки игры и `Launcher/launcher.log`, укажите версии и шаги воспроизведения. Особенно полезны записи `UNSUPPORTED BUILD`, `HOTSEAT FAILED` и `DRAFT PROGRESS RESET FAILED`. Строка `HANDOFF COMPLETE` подтверждает выполнение кода, но доступность экрана второго игрока проверяется в самой игре.

<details>
<summary>Проверка SHA256 в PowerShell и действия при новой сборке</summary>

Откройте PowerShell в папке `Launcher`. Замените пример пути на свою папку игры:

```powershell
$gamePath = 'C:\Games\Heroes of Might and Magic Olden Era'
$actualHash = (Get-FileHash -LiteralPath (Join-Path $gamePath 'GameAssembly.dll') -Algorithm SHA256).Hash
$modManifest = Get-Content -LiteralPath '..\Mod1\mod.json' -Raw | ConvertFrom-Json
$actualHash
if ($actualHash -ieq $modManifest.gameAssemblySha256) {
    'GameAssembly.dll совпадает. Далее выполните игровые проверки.'
} else {
    'Другая сборка игры. Нужна проверка и адаптация мода.'
}
```

Для версии 0.2.1 поддерживается SHA256:

```text
bb4ea1f5b28af6b3f21031bb53f7fa50021579a8c74ade2f05904696d6fdb38a
```

При изменении файла разработчику нужно проверить адреса вызываемых и перехватываемых методов, их сигнатуры, смещения полей и используемые значения режимов в новой IL2CPP-сборке. Затем адаптировать исходник, обновить `SupportedHash` в `Mod1/src/ArenaHotseat.cs` и `gameAssemblySha256` в `Mod1/mod.json`, собрать DLL и пройти игровые проверки. При обновлении Unity или BepInEx отдельно проверяются загрузчик и его библиотеки.

Скрипт сборки мода обновляет хеш DLL в `files[].sha256`; он не определяет совместимость с новой игрой. Для отчётов можно использовать папку `Mod1/verification`.

## Как удобнее публиковать на GitHub

Рекомендуемый формат: **исходники в репозитории, готовый ZIP для игроков в Releases**. GitHub Releases позволяют прикрепить готовые файлы к версии и добавить описание изменений; автоматический архив `Source code (zip)` содержит содержимое репозитория на момент тега. [Документация GitHub](https://docs.github.com/en/repositories/releasing-projects-on-github/about-releases).

**В репозитории** сохраните папки `Launcher` и `Mod1` рядом: так устроены обнаружение модов и сборка. Добавьте исходники обеих частей, `build.ps1`, `OldenEraLauncher.exe.config`, `runtime/runtime.json`, `mod.json`, документацию и `.gitignore`. В корневом README разместите краткое описание, ссылку на готовый релиз и инструкцию запуска. Для собственного кода выберите `LICENSE`; зависимости перечислены в [THIRD-PARTY.md](THIRD-PARTY.md).

**Для игроков** прикрепляйте к релизу архив вида `OldenEra-ArenaHotseat-0.2.1-win-x64.zip` с такой структурой:

```text
OldenEra-ArenaHotseat-0.2.1/
  Launcher/
    OldenEraLauncher.exe
    OldenEraLauncher.exe.config
    README.md
    THIRD-PARTY.md
    runtime/                  (целиком, включая runtime.json)
  Mod1/
    mod.json
    README.md
    payload/                  (с ArenaHotseat.dll внутри)
```

К комплекту добавьте файлы лицензий распространяемых зависимостей. Укажите в описании релиза версию мода, поддерживаемую сборку игры и SHA256 `GameAssembly.dll`, изменения, результаты проверки и известные ограничения. SHA256 самого ZIP можно приложить отдельным файлом `SHA256SUMS.txt`.

В исходниках не нужно хранить собранные EXE/DLL и весь бинарный `runtime`: их удобнее распространять в готовом релизе. Исходные `GameAssembly.dll`, игровые ресурсы, дампы и сохранения в комплект не входят.

Собирайте публичный ZIP в отдельной папке, копируя только перечисленные файлы. Не включайте личные `settings.json`, `state.json`, `backups/`, `transactions/`, `pending-transaction.json`, `.work/`, `monitor/`, журналы, `status-output.json`, `last-error.txt` и сгенерированный `compiler.rsp`. **Не удаляйте эти файлы из своей рабочей установки ради упаковки.** Перед публикацией проверьте распакованный ZIP как новый пользователь: обнаружение мода, выбор папки игры, включение, запуск и отключение.

## Восстановление

Мод меняет поведение в памяти процесса: оригинальные `GameAssembly.dll` и `Core.zip` на диске не переписывает. Лаунчер устанавливает DLL мода и общий загрузчик.

- Перед заменой существующего файла лаунчер сохраняет резервную копию в `backups`. Отключение восстанавливает её; добавленные файлы удаляются по точному списку.
- Если файл изменили Steam или другой инструмент, лаунчер отказывается перезаписывать его старой копией и сообщает об этом.
- Прерванная операция записана в `pending-transaction.json`. Повторное нажатие **Применить** запускает её восстановление до начала новой операции.
- Не удаляйте `state.json`, `backups` и `transactions`, пока включены моды или есть незавершённая операция.
- Существующая сторонняя установка BepInEx автоматически не перезаписывается. Для неё нужна отдельная интеграция или чистая копия игры.
- Сгенерированные BepInEx конфигурации, журналы и interop-кэш остаются после отключения. Файл подключения `winhttp.dll` удаляется вместе с управляемым загрузчиком, поэтому эти каталоги сами по себе не включают моды.

Настройки лаунчера сохраняются в `settings.json`, список установленных файлов — в `state.json`, журнал — в `launcher.log`.

<details>
<summary>Для разработчиков: сборка, CLI и дополнительные моды</summary>

Исходники лаунчера: `Launcher/src`. Из папки `Launcher` выполните `powershell -NoProfile -ExecutionPolicy Bypass -File build.ps1`; используется компилятор .NET Framework.

Исходники мода: `Mod1/src`. Из папки `Mod1` выполните `powershell -NoProfile -ExecutionPolicy Bypass -File build.ps1 -DotNetSdkRoot <папка-SDK-.NET>`. Использовался SDK .NET 8; аргумент указывает на папку, содержащую `dotnet.exe` и `sdk`. Зависимости берутся из соседней `Launcher/runtime`, которую нужно предварительно получить из готового комплекта той же версии. Скрипт обновляет SHA256 собранной DLL в `mod.json`.

Команды лаунчера:

- `--apply <папка-игры> [id-мода ...]` — применить указанный набор модов; без id отключить все управляемые моды. Перед изменением закройте игру.
- `--check <папка-игры>` — проверить готовность установленного набора к запуску: состояние файлов, хеш игры для включённых модов и их payload. Игра не запускается. Проверяются только уже включённые моды из `state.json`; при отключённом моде код 0 не подтверждает его совместимость.
- `--status` — записать текущее состояние в `status-output.json`.
- `--smoke <временная-папка>` — проверить файловые операции на автоматически созданных тестовых файлах. Установленная игра не используется. Результат записывается в `smoke-results.json` в указанной папке. Это проверка лаунчера, а не игровых сценариев мода.

Пути с пробелами заключайте в кавычки. Код завершения 0 означает успех, 1 — ошибку; при ошибке CLI записывает `last-error.txt`.

Чтобы добавить другой мод, создайте рядом с `Launcher` папку, например `Mod2`, с `mod.json` и файлами `payload`. Каждый элемент `files` описывает `source` относительно папки мода, `target` относительно папки игры и `sha256` исходного файла. Пути должны быть относительными, без переходов `..`, junction или символических ссылок.

Для DLL-плагина BepInEx задайте `requiresBepInEx: true`; лаунчер добавит общий загрузчик. Разные моды не могут устанавливать разные байты в один путь. Пример — `Mod1/mod.json`. SHA256 файла можно получить командой `Get-FileHash -Algorithm SHA256`.

</details>
